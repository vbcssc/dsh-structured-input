# 结构化输入 · dsh-structured-input

一个 [DSH](https://github.com/deepseek-ai) 插件：**点一下按钮，把你这一刻的需求连同当前会话的上下文，按模板嚼成结构化提示词。**

> **你写的**：照刚才那个改，颜色不对
>
> **它生成的**：
>
> ```markdown
> ## 目标
>
> 把上一轮新增的状态标签改成与设计稿一致的配色。
>
> ## 背景与现状
>
> - 上一轮已经给列表项加了状态标签，结构和文案都确认过，问题只在颜色。
> - 当前标签仍是默认灰色，与页面的主题强调色不一致。
> - 标签的内边距、圆角、字号不需要再动。
>
> ## 要求
>
> 1. 只改配色，不改结构、文案、内边距和圆角。
> 2. 进行中、已完成、已失败三种状态各用一种可区分的颜色。
> 3. 色值集中到主题样式变量里，不在组件中散落硬编码。
>
> ## 约束
>
> - 沿用现有的主题变量机制（CSS 自定义属性），不引入新依赖。
> - 浅色与深色主题都要适配，文字保持可读。
> - 不修改其他组件的样式。
>
> ## 验收标准
>
> - 三种状态在浅色、深色主题下都能一眼区分，文字清晰可读。
> - 标签的结构与文案与改动前完全一致，只有颜色变化。
> - 色值定义位置符合项目现有约定。
> ```

## 它解决什么问题

光看你这一句话，模型不知道该干什么 —— 「刚才那个」是什么、「颜色」指的是哪个元素。
这个插件在生成之前**先把当前会话的历史读一遍**，把已经聊过的东西压缩成背景，
再按你选的模板重新组织。

DeepSeek 类模型在结构清晰、分节明确的中文提示词下，输出质量通常更稳定。

## 怎么用

1. 输入框左边工具栏点 **「结构化」**（就在「硬邦邦」旁边）。
2. 弹窗里选模板、写下需求。
3. 点 **「生成」**。等几秒。
4. 结果可以 **复制** 走，也可以直接 **发送** 进当前会话。

弹窗里会显示这次带了多长的上下文：

```
上下文：已带上 12 条历史，更早的 3 条已省略
```

如果显示「没有可用历史，只用当前需求」，说明这是会话的第一条消息，或者宿主没能读到会话。

## 和「硬邦邦」插件的区别

| | 硬邦邦（dsh-prompt-hardener） | 本插件 |
|---|---|---|
| 触发时机 | 你按发送，它半路劫持 | 你点按钮，主动打开 |
| 做什么 | 把话改成暴躁硬汉风格 | 把话改成结构化格式 |
| 改上下文吗 | 不改写历史 | **读历史**，用来理解指代 |
| 碰发送链路吗 | 会（pre-step 改写） | **不碰** |

**两个可以同时开。** 但要注意：硬邦邦如果在「自动」模式下，本插件发出去的结构化结果会被它再改写一遍（它会硬邦邦化任何用户消息）。同时用的时候建议把硬邦邦切到「审查」模式，或者干脆关掉。

## 模板

模板在 `~/.dsh/structured-input/templates.json`，首次启动时从包内播种一份。**直接改这个文件就行**，下一次生成立刻生效，不用重启。

格式：

```json
{
  "templates": [
    {
      "id": "task",
      "name": "任务（通用）",
      "sections": [
        { "title": "目标", "hint": "一句话说清最终要达成什么" },
        { "title": "约束", "hint": "技术栈、平台、不能动的东西" }
      ]
    }
  ]
}
```

- `title` 会**原样**成为结果里的小节标题，也会被要求原样成为模型输出的 JSON 键。
- `hint` 会拼进给模型的说明里，帮它知道这一节该写什么。可以不写。
- 也接受裸数组写法（没有外层 `templates` 键）。
- 重复的 `id` 只保留第一个。

内置四个模板：任务、缺陷修复、功能开发、代码审查。

## 提示词

`~/.dsh/structured-input/prompt.md` —— 同样可以直接改，改完立刻生效。

代码里还拼了一份**保真约束**（`index.js` 的 `FIDELITY_CLAUSE`），它不随 `prompt.md` 变化：
技术要求不许篡改、上下文只用来理解指代、只输出 JSON。这是防止「换了个提示词就开始编」的兜底。

## 上下文预算

弹窗里有一个**上下文档位**下拉，决定这次生成带多少会话历史：

| 档位 | 条数 | 字符上限 | 适合 |
|---|---|---|---|
| 不带上文 | 0 | 0 | 这次的需求完全独立，前文只会干扰 |
| 最近 5 条 | 5 | 4000 | 只改一句、只调个颜色 |
| 最近 10 条（默认） | 10 | 12000 | 常规任务 |
| 最近 20 条 | 20 | 24000 | 需求跨了好几轮才说清 |
| 尽可能多 | 不限 | 48000 | 需要挖很早之前的约定或已排除的方案 |

两个上限**同时生效**：条数管住"别把几十轮闲聊全拉进来"，字符管住"别让一条巨型工具输出
吃掉全部预算"。超了就从**最老的**开始丢，并在开头标一句「更早的 N 条对话已省略」。

档位是**按次**的：只影响本次生成，不改默认值。想让默认值变，就改 `state.json` 里的
`context.preset`（见下）。老版本的 `context.maxChars` 仍然认 —— 会按「向上取最近一档」
迁移，不会悄悄失效。

> **为什么是固定档位而不是让用户填字符数**：12000 和 24000 的差别对用户没有直觉，
> 而"最近 5 条 / 10 条 / 20 条"是看得懂的。

只保留：
- 用户和助手的文本
- 工具调用压成一行 `[调用工具 read]`（参数不保留）
- 图片、文件保留占位符

丢弃：推理过程、工具结果全文、系统注入的上下文消息。

> **为什么不把 `Message[]` 原样塞给模型**：那样模型会看到自己上一轮的 `tool-call`，
> 然后接着调工具，而不是老老实实输出结构化文本。

## 模型路由

按三级顺序找模型：

1. 插件配置里的 `llm.provider` + `llm.model`（两个都给才算数）
2. 当前会话已经落库的请求头（用户切模型会跟进）
3. 宿主默认模型（设置里选的那个）

绝大多数情况走第 3 条，不需要配。

## 配置文件

`~/.dsh/structured-input/state.json`：

```json
{
  "enabled": true,
  "templateId": "task",
  "context": { "preset": "standard" },
  "llm": { "provider": "", "model": "", "maxTokens": 0, "timeoutMs": 60000 }
}
```

- `context.preset` = 默认上下文档位，取值 `off` / `brief` / `standard` / `deep` / `full`。
  写错了会回落到 `standard`，**不会**回落到 `off`。
- 老版本的 `context.maxChars`（自由字符数）仍然兼容，会按最近一档迁移。
- `maxTokens: 0` = 按输入长度自动估算
- `timeoutMs` = 单次生成的超时

## 安装（桌面版）

1. 侧边栏 **插件** → **添加插件**
2. 包名填 `dsh-structured-input`（本地开发用 `link:` 指向源码目录）
3. 启用并重启 DSH

手工接线（本次用的方式）：在 `~/.dsh/profiles/desktop/package.json` 里加

```json
"dependencies": { "dsh-structured-input": "link:D:/docker_and_big_models/开源仓库-分析区/dsh-structured-input" },
"dsh": { "profile": { "bundles": [ "...", "dsh-structured-input" ] } }
```

然后在该目录跑 `pnpm install` 并重启宿主。

源码目录已从 `~/.dsh/plugins/dsh-structured-input` 迁到上面的仓库目录。
`link:` 必须指向**当前**位置 —— 指到旧路径会让 profile 加载一个失效链接。

## 路由

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/plugins/dsh-structured-input/state.json` | 读状态与模板清单 |
| POST | `/plugins/dsh-structured-input/state.json` | 写状态 |
| POST | `/plugins/dsh-structured-input/generate` | 生成结构化提示词 |

## 测试

```sh
node --test test/*.test.mjs
```

覆盖上下文投影（裁剪、工具调用压缩、空历史）与结构解析（围栏、抠大括号、降级路径）。

## 已知限制

- 上下文只在**用户已发送过消息**的会话里有内容。新会话第一次生成必然是「只用当前需求」。
- 会话必须处于已保留状态（`sessions.scope(id)` 能解析出作用域），否则点「发送」会提示不可用。
- 模型返回的 JSON 结构不对时不会报错，而是降级成「模板骨架 + 原文」，并在弹窗里显示黄色警告。
